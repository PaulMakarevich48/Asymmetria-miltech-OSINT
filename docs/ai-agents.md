# Работа с ИИ-агентами

Продукт написан одним человеком вместе с агентами Claude Code: сотни сессий за четыре месяца, часть — с телефона. Скорость здесь не главное. Главное — чтобы агенту можно было доверить работу на живой системе с подписчиками, деньгами и ключами.

## 1. Граница, а не правило

Правила в инструкции агент может забыть или обойти по ошибке. Поэтому важное держится на границах, которые не зависят от его памяти:

- **Песочница ОС на каждую команду.** Агент не видит ключей, сессий Telegram и базы подписчиков, не может писать в прод-копию и служебные скрипты, ходит в сеть только к API моделей.
- **Отдельный пользователь для прода.** Бот, прогоны и портал работают из клона, который агенту не виден. Код попадает туда только выкаткой.
- **Выкатка — кнопкой в боте у владельца**, через исполнитель, который сам проверяет коммит: импорт всех модулей, тест прав доступа к боту, гейт лаборатории, окна прогонов, откат одной командой.
- **Вне песочницы исполняется только каталог служебных скриптов**, без импорта кода рабочей копии: иначе правка агента исполнилась бы у пользователя с правами администратора.

## 2. Лаборатория вместо «вроде работает»

Любая правка пути выпуска сначала прогоняется в лаборатории: тот же день, тот же код и промпты, полная сборка — без публикации, со своим суточным потолком трат и сравнением с опубликованным. Зелёный прогон оставляет отметку на коммит; без неё гейт выкатки не пропустит правку. Прогон, начатый без денег на весь цикл, не начнётся вовсе: два оборванных на середине прогона — это потерянные деньги без отметки.

## 3. Журнал уроков

Каждая авария записывается: что сломалось, почему, что из этого следует. Вывод становится кодом или тестом, а не запиской. Пример цепочки: подпись под фото в PDF шесть раз оказывалась не про тот кадр; пять раз чинили конкретный путь, на шестой — правило («подпись — то, что опознано на кадре»), проверенное прогоном по всему архиву, а не по одному случаю.

## 4. Деньги

- Учёт стоимости каждого вызова модели по назначению — себестоимость выпуска, бота, графа видна по дням.
- Рубильники по тратам: прогон, превышающий порог, не стартует.
- Модель выбирается замером на своих задачах: перевод разбора постов на новую модель дал ×3–5 экономии при том же числе сущностей — проверено на тех же постах, а не по рекламе.
- Большие разовые работы (чистка графа, распознавание сканов каталогов, досье компаний) — волнами агентов на подписке, а не через платный API, — с поправкой на пятичасовое окно лимита и автопродолжением после его сброса.

## 5. Проверка ИИ на ИИ

- **Сверщик выпуска**: каждое утверждение выпуска сверяется с постом-источником и справкой графа; правка — моделью, затем пересверка правки.
- **Проверка прогнозов на архиве**: разные модели строят проекции по прошлому окну, слепой судья сверяет их с тем, что случилось. Так выяснилось, что самая дорогая связка моделей не прибавляет точности, — и решение о цене принималось по данным.
- **Независимый поставщик**: второй вендор моделей как резерв и как критик — у него другие ошибки.

## 6. Документы, которые читает агент

| Документ | Роль |
|---|---|
| карта проекта | где что лежит, что запрещено, как выкатывать |
| план | единственный список задач: номер, суть, состояние, следующий шаг |
| бэклог | обоснования и замеры под теми же номерами |
| журнал | что сделано, по дням |
| уроки | аварии и выводы |
| реестр агентов | кто из агентов что может и что ему запрещено |

Вторых списков задач нет: когда их было пять, они противоречили друг другу. Когда план разросся до 190 КБ и перестал читаться целиком, его ужали до сути, а историю перенесли в бэклог.
